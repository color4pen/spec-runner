## Key Invariants Verified (no violation)

### C1: run/job-start handler unification

- `runJobHandler` is one function shared by both commands.
- Each command entry keeps its own `positional.name` (`"request.md|slug"` vs `"slug|file"`), so `--help` output is preserved.
- Worktree detection guard (`bin/specrunner.ts` detectWorktree) operates at the CLI entry layer, before the handler; unaffected by handler consolidation.

### C2: compute\*Iteration deletion

- Each deleted function returned `(state.steps?.[STEP_NAME]?.length ?? 0) + 1`.
- `nextIteration(state, STEP_NAMES.X)` in `io-iteration.ts` is the same formula.
- All four files already imported `nextIteration`; no import changes required.

### C3: detectPackageManager phase-1 → findLockfile

- `findLockfile` has byte-identical walk logic: same `LOCKFILE_MAP` iteration order, same `.git` stop, same filesystem-root stop.
- `detectPackageManager` passes its `fs` parameter (satisfies `{ existsSync }`) to `findLockfile`; no abstraction mismatch.
- When `findLockfile` returns `null`, fall-through to phase-2 is identical to original loop exhaustion.

### C4: loadConfig delegation

- `loadConfigWithSourceMetadata` has the same `if (repoRoot)` guard around the project-local file read.
- Both original `loadConfig` and `loadConfigWithSourceMetadata` throw `configMissingError()` when neither file exists.
- Returned `.config` field is built by the same read → migrate → merge → validate chain.

### C5: journal append consolidation

- `appendEventRecord` appears exactly once in `job-journal.ts` (inside `_appendRecord`).
- `this.resolver.getEventsPath()` is a pure computation (deterministic path from construction-time fields); calling it per-append vs once is equivalent.
- `_writeAllToJournal` now routes through `_appendRecord`, keeping the same target path.
- Four named public methods (`appendInterruption`, `appendLineage`, `appendOperatorEvent`, `appendFindingRecency`) retain their original signatures; callers and test assertions are unaffected.
- `EventRecord` union includes all four specific record types — type widening at `_appendRecord` is safe.

### C6: verification runner tail extraction

Skip strings generated by template:
```
`_(skipped — previous ${args.skipLabel} failed)_`
```

- `skipLabel: "command"` → `"_(skipped — previous command failed)_"` — byte-identical to original `runVerificationCommands` literals ✓  
- `skipLabel: "phase"` → `"_(skipped — previous phase failed)_"` — byte-identical to original `runVerificationPhases` literals ✓

`coverageSkipNote` is declared inside `finalizeVerificationRun`, set only in the `coverage === undefined` else branch, and forwarded to `writeVerificationResult` — same scoping as original.

`failed` is destructured as a local mutable variable; gate results mutate it the same way as original.

`phases` array is passed by reference; `finalizeVerificationRun` appends to it and returns a `result` that includes it — same data flow as original.

The skip strings inside the commands/phases loop (for fail-fast-skipped subsequent commands/phases) were NOT moved into `finalizeVerificationRun` and remain unchanged.

### C7: worktreePath resolution helper

- `resolvedSlug ?? ""` correctly converts `null` to `""` (falsy), preserving the original `if (!resolvedWorktreePath && resolvedSlug)` guard semantics.
- `updatedState` passed as `state` argument; `state.worktreePath` accesses the same field.
- `resolveLivenessWorktreePath` returns `Promise<string | null>` — assigned to `const`, not `let`, in both callers; no reassignment was present after the original if-block either.

### C8: Dead code removal

- `PROBE_SLUG` alias removed; both call sites now use `VALIDATOR_PROBE_SLUG` directly — grep 0 for standalone `PROBE_SLUG` in `src/` and `tests/`.
- Empty if-block in `job-state-projection.ts`: condition body was a comment only; `storedCounters` was used nowhere else; removing both is a pure no-op.
- `enrichContext` identity method retained in `spec-review.ts` (tests require it).
